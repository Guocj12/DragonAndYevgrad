## 三、深渊与结算

```
cap(k)  = 2.49 × 10^E_k          E = [249, 2492, 24920, 249209]
y(k,0)  = 0.5 × log10 cap(k)     每轮初始 50% 指数进度
D(k)    = log10 cap(k) − y(k,0)
τ       = 249 / ln2 = 359.3 s

每个 tick（0.05s）：
  1. mtc += prod × dt × mtcGain
  2. S   -= (prod × η + 白琦伤害 + 恒伤害) × dt
  3. S   *= 10^( D·e^(t/τ)/τ × dt )        // 超指数：增速的增速也在加快
  4. S ≤ 0 → 守护（进下一档）；S ≥ cap → 覆灭（回档 0）
  5. 资源结算：MP/PP/AP
```

- 零产量满档时间恒为 **249 秒**（tier 0 的 249 来自 `e249`；更高档同样 249 秒，因为 τ 固定、
  跨度 D 与 e^(t/τ) 同步放大）。
- S 的乘法增长在对数空间做（`pow10(log10 S + rate·dt)`），否则 `Math.pow(10, 3000)` 会溢出成 0，
  直接误判为「守护」。
- 覆灭只清 mtc 与升级等级；科技（MP）与科技树（AP）永久保留；249 的「记忆复用」是数据库升级，
  不随覆灭清零（对应 10_设计 §9.1）。

资源：

| 资源 | 获取 | 用途 |
|---|---|---|
| mtc | 产量累加 | 升级（覆灭清空） |
| MP | 覆灭：`(1 + 8×本轮最高净化率) × MP 倍率` | 科技（永不重置） |
| PP | 守护：`12 × (档位+1) × PP 倍率` | 通用科技树 |
| AP | 每档首次守护 +1/+2/+4/+8，首次覆灭 +1 | 角色科技树（可重置返还） |

## 四、数值为什么和 09 公式版不一样

`09-完整设计-公式版.md` 里「升级 ×1.10^L、成本 ×3^L」这类表跑不通：效果对数斜率远小于成本对数斜率，
每买一级都在亏，mtc 指数永远追不上 1e125，更别说 1e124604。改成下面前提后曲线才闭合：

1. **恰好一条主链**（灌装线 / 剑意 / 骨钉）：效果 ×2^L、成本 ×2^L。
   于是「产量 ≈ κ · mtc」，κ 由永久乘区决定，这决定了每轮 y 的爬升速度。
   如果第二条升级也按 ×2^L 成长，经济立刻变超临界 —— 任何档位都会在几秒内通关，档位门禁失效。
2. **其余升级一律有界**：饱和曲线 `×(1 + a·L/(L+60))`、log 型加成、`t/(t+60)` 型时间加成。
   每件最多 ×1.2~2，合计把 κ 抬到个位数。它们在前期很香，后期自然边缘化（和 AD 的早期升级一样）。
3. **跨轮成长的唯一主驱动**：249 科技「增产」里挂的 `memoryBase^覆灭次数`（记忆累积，全产量乘区）。
   它让「重置次数」直接换成产能，是 10–15 小时节奏的调速旋钮。
4. **战斗角色的标度**：白琦用 `2^等级` 的剑意通道（不吃 mtc 反馈，安全）；
   恒的战力 = `10 × (S/S0)^α × 战力倍率`，α 有硬上限（`TUNING.alphaCap = 0.55`）。
   α ≥ 1 时恒会「深渊越强他越强」到反超深渊、任何档位都能单刷，所以必须压在 1 以下。
5. **全局数值旋钮**（都在 `src/db.js` 顶部 `TUNING`，可用环境变量覆盖，便于扫参）：
   `memoryBase`（默认 1.006）、`alphaCap`（0.55）、`flavorScale`（1）、`mainCost`（2）。

> 结构没动：每个角色仍然是 8 升级 + 4 科技 + 9 科技树节点，三层职责与 `10-设计原话` 一致。
> 改的只是曲线与常数（`11-下一步执行指令 §四.4` 允许）。

## 五、贡献面板的语义

AD 的数据页按「乘区」看贡献。这里主链（灌装线/剑意/骨钉）与 mtc 同阶，任何时刻都占 ~100%，
如果直接算占比，面板永远只有一行 —— 所以：

- 主链单独列为「主链（与 mtc 同阶，中性）」，**不计入占比**；
- 其余加成之间互相比较，面板会提示「单一加成占比超过 50%」；
- 「净化」页合并了产量加成与净化效率（因为净化量 = 产量 × η）。

实测（value 策略，覆灭 6 轮之后、每 60 秒采样一次）：**非中性单项最大占比 36.8%**（「开张」）。

## 八、已知问题 / 下一步

1. **档位时长分布极不均匀**：档 3 占 10.7h。这是「每档指数 ×10 + 每轮固定 249 秒上限」的必然结果。
   如果要在四档之间摊平，只能动结构（例如提高高档的单轮时长上界），本轮没动。
2. **cheapest 策略超时**：17.7h。想把笨策略拉回 15h 内，可下调 `memoryBase` 到 1.004 左右
   （会让 value 掉到 ~11h）。
3. **科技树深层节点的「强度递增」靠机制而非数值**：`hga6 深渊骑士`（吸取深渊转本轮战力）已接进 tick，
   `bqa9 屠龙者`（每分钟把深渊对数进度压低 8%）已接进 tick；其它深层节点是「记忆奇点 ×2 + mtc^0.5」
   「万事屋本店互哺」「真龙叠层」这类机制效果，数值上不再叠 ×10 —— 与 `10-设计原话 §八`「大胆一点」一致，
   但如果要严格的「深层数值 > 浅层数值」，需要在下轮把 4/5 层节点再抬一档。
4. **结局、成就、剧情、双禁**：按 `10-设计原话 §十三/§十五` 与 `11 §二` 的范围，本轮不做。
5. **前端没做自动化测试**：只做了语法检查与 HTTP 200 冒烟，交互靠手工。存档结构有 `v` 字段，
   后续改动请写迁移。

## 九、前端：套 AD 的壳

第二轮把前端换成了 AD 的壳。结论先说：**AD 的 `.vue` 组件不能直接跑**——
它们是用 vue-cli + webpack 编译的 SFC，且模板里到处引用 AD 自己的全局对象
（`player`、`GameUI`、`Tabs`、`TimeStudy`、`Theme`、`Pelle`…）。要「原样复制粘贴」得先
`npm ci` 装 ~1GB 依赖、再把这些全局对象一个个喂给它，成本比重写还高。所以采用的做法是：

**壳照搬，内容重写：**
- 样式表原样复制：`ref/AD/public/stylesheets/` → `web/shell/stylesheets/`（含字体、图标、`styles.css` + `old-ui.css`）
- 图片/图标原样复制：`ref/AD/public/images/` → `web/shell/images/`、`icon.png` → `favicon.png`
- 运行时同一版本：`vue@2.6.14` 的 `vue.min.js` 放进 `web/shell/vue.min.js`（和 AD 一样用字符串模板）
- 类名/版式沿用 AD 约定：`o-primary-btn`、`o-tab-btn`、`o-tab-btn--active`、
  `o-tab-btn--secondary`、`c-subtab-button-container`、`c-old-ui`、`l-old-ui`、`l-old-ui__page`、
  `c-progress-bar` 这一套；配色全部走 AD 的 CSS 变量（`--color-accent` / `--color-good` / `--color-bad` …）
- 组件按 AD 的结构重写（Vue 对象 + 模板字符串），没有引入任何构建步骤

## 十二、第二轮改动（2026-10-22 晚）

### 12.1 升级解锁链（解决「进游戏一脸懵」）

- 数据：`src/db.js` 里每个角色的升级按索引给出前置等级 `REQ_LEVELS = [0, 3, 3, 3, 4, 5, 6, 8]`
  （第 i 个升级需要第 i-1 个达到 N 级），写进 `upgrade.reqLevel`
- 引擎：`Engine.upgradeUnlocked(charId, idx)` + `buyUpgrade` 前置检查（没解锁返回 0）
- UI：未解锁的卡片灰掉，右上角显示「未解锁」，底部红字「需要「灌装线」Lv3」
- 效果：开局只有 1 个升级能点，之后按 3→3→3→4→5→6→8 级逐步放开，玩家有时间看效果

### 12.2 剧情播放器（数据驱动）

- 数据：`src/story.js`，每条 = `{ id, trigger, mode, lines[] }`
  - `trigger.type`: `firstRun` / `guard` / `collapse`，可带 `tier`（第几档）与 `count`（第几次）
  - `mode`: `fullscreen`（全黑屏居中白字）/ `bottom`（只遮下方 1/3 屏幕）
  - `lines`: 多段连续文本，点击继续，最后一段点完自动消失
- 引擎：`enqueueStory()`（守护/覆灭时按 tier+count 匹配）、`nextStory()`、`finishStory()`、

## 二十一、升级体系重做：无限等级 + 成本 ×2..×9（2026-10-23 深夜）

### 21.1 先回答"什么时候封的顶"

`UP_CAP = 10`（8 个升级全部 10 级封顶）是在 **`d4ab78b feat(data): 添加角色/升级/科技/科技树数据表`**
这次提交里就写死的，不是后来改的。`6497992` 只是把描述改成「10 级上限」，让它在 UI 上显形。

### 21.2 新规则（按设计者要求）

| 项 | 规则 |
|---|---|
| 等级上限 | **无**（所有升级都能一直买） |
| 每级成本倍率 | 升级 1 ×2、升级 2 ×3 …… 升级 8 ×9 |
| 基础价 | 全部为 1 |
| 解锁条件 | 前一个升级达到 10 / 20 / 30 / 40 / 50 / 60 / 70 级 |
| 每级效果 | `R^(1/8)`，R 是该升级的成本倍率 |

每级效果：1.09 / 1.15 / 1.19 / 1.22 / 1.25 / 1.28 / 1.30 / 1.32（后面越来越强）。

### 21.3 为什么效果必须是 `R^(1/8)`

设玩家在某项上花 M，等级 `l = log M / log R`，贡献 `e^l = M^(ln e / ln R)`。
要让 8 项**在同一个 mtc 数量级下贡献相同**，指数必须相同，记为 c：

- 8 项都买时总产量 `P = M^(8c)`，总成本是 M，所以 `8c = 1` → **c = 1/8**；
- c > 1/8 → 总产量超过成本（超临界，几秒通关）；
- c < 1/8 → 产量追不上成本（卡死）。

**这是唯一解，不是拍脑袋的系数。**

### 21.4 两个被否掉的方案（实测）

| 方案 | 结果 |
|---|---|
| 全项同贡献 `R^(l/8)`，但保持旧 `memoryBase=1.006` | 40 小时未通关（577 轮）：单轮里只有 1 项可买时 `P = M^(1/8)`，产量推不动 |
| 主链 `×2/级` + 其余 7 项 `R^(0.0125·l)` | **4 分钟通关**：8 个乘区叠加，P/C 直接超临界 |

结论：这个游戏的 P/C 本来就是临界值，8 个乘区同时无限增长极其敏感。

### 21.5 落地参数

- `memoryBase` 1.006 → **1.45**（每覆灭一次，全产量 ×1.45）。同贡献把单轮产能压低了，
  跨轮科技必须补上这块，否则单轮推不动。
- 实测（`node sim/simulate.mjs <策略> 40 0.5`）：

| 策略 | 通关 | 总时长 | 轮数 |
|---|---|---|---|
| value | ✅ | **11.51h** | 170 |
| cheapest | ✅ | **11.44h** | 169 |
| preset | ✅ | **11.58h** | 171 |

### 21.6 代价（需要设计者知道）

1. **策略差异消失**（11.44 / 11.51 / 11.58，差 1%）。因为每项的「贡献/成本」完全相同，
   买哪个都一样——这是"同贡献"的必然结果，之前"三种策略差 20–50%"的验收标准不再适用。
2. **前期更依赖跨轮科技**：单轮内 8 项买不起太多，主要靠覆灭累积。
3. 暴击 / 真龙 / α 这几类「有上限」的效果已从升级上移除（它们会破坏同贡献），
   相关机制仍由科技与科技树提供（`bqa3`、`bqa6`、`bqa7`、`bqa8`、`hga2`、`hga5` 等）。
