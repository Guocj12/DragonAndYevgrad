## 0. 结论摘要

1. **两边是同一款游戏，而且咬得比预期更紧。** 数值的四层 ↔ 剧情的档 0–3；数值每层 8 项的 kind 语义，正好是四个角色的机制：第一层（档 0 / 249）生产 + 资源转化，第二层（档 1 / 耶维奇）生产 + 全体效率，第三层（档 2 / 白琦）单次削减 + 削减回收，第四层（档 3 / 恒）削减频率 + 敌方转化（频率上限 20 次/秒、溢出转伤害 ↔ 恒的"攻速超 20 转伤害"；敌方转化随深渊强度增强 ↔ 恒"深渊越强恒越强"）。**32 项 = 4 角色 × 8 项，一一对应，不用重排。**
2. **框架要拆掉的是"永久层"和"输入方式"，不是角色页。** 数值只有两套永久（失败 F[4] / 成功 U[4] + 双钱包 WF/WS），框架有 MP / PP / AP 三套永久资源 + 每角色 4 科技 + 9 节点科技树 + 通用树 12 节点 + 万事屋兑换 + 手动生产 + 批量购买。这些在数值里没有对应，**必须删或降级为纯展示**；角色页 / 档位 / 剧情播放器 / 存档外壳可以留。
3. **真正要新写的是"层内片段"这一层。** 数值的核心是一个 9 步的 20Hz 片段循环（解锁扫描 → 最便宜循环购买 → 效果 → 力量/资源 → 压力 → 单次攻击 → 回收 → 判胜 → 结算），框架现在的 tick 顺序（产量→mtc→战斗→深渊增长→边界→自动购买）与之完全不同，`tick()` 要按数值重排，**不能打补丁式改**。
